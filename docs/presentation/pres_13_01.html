Проблема оптимизации компилятора

Масштаб проблемы

  • Современные компиляторы содержат 150–200+ проходов оптимизации (GCC, LLVM)
  • Стандартные уровни (-O1, -O2, -O3) — фиксированные последовательности
  • Они оптимальны в среднем, но не для конкретной программы

Комбинаторный взрыв (n = 50 проходов)

Выбор проходов: 2n комбинаций
при n=50 → ~1015 вариантов
Упорядочивание: n! перестановок
при n=50 → ~1064 вариантов
Ключевая сложность: проходы не независимы — они взаимодействуют друг с другом. Один проход может создавать или уничтожать возможности для другого.

Обзор существующих подходов

Wang & O'Boyle (2018)
"Machine Learning in Compiler Optimisation"
• Систематизация ML-подходов: feature engineering → обучение модели → deployment
• Классификация методов: supervised (регрессия, классификация), unsupervised (кластеризация), reinforcement learning
Ashouri et al. (2018)
"A Survey on Compiler Autotuning using Machine Learning"
• Формализация двух проблем: selection problem (2n) и phase-ordering problem (n!)
• Обзор 200+ работ: итеративная компиляция, генетические алгоритмы, байесовские сети

Ограничения существующих подходов

Метод Что делает Что не объясняет
Итеративная компиляция Находит хорошие комбинации Почему они работают
ML-предсказание Корреляции features → performance Каузальные механизмы
Генетические алгоритмы Эволюция последовательностей Структуру взаимодействий

Цель и задачи исследования

Цель работы

Исследовать каузальные зависимости между оптимизирующими проходами LLVM и построить граф их взаимодействий для понимания структуры оптимизационного пространства.

Задачи

  1. Собрать датасет экспериментов с различными комбинациями проходов на стандартных бенчмарках
  2. Применить методы каузального вывода для оценки эффектов отдельных проходов
  3. Выявить enabling-зависимости (проход A создаёт возможности для B) и disabling-зависимости (проход A блокирует B)
  4. Построить граф каузальных зависимостей между проходами
  5. Валидировать результаты на отложенной выборке

Формальная постановка задачи

Определения

Пусть P = {p₁, p₂, ..., pₙ} — конечное множество оптимизирующих пассов компилятора.
Пусть 𝒳 — пространство программ, x ∈ 𝒳 — конкретная программа.

Вектор воздействий (treatment vector): T = (T₁, T₂, ..., Tₙ) ∈ {0, 1}ⁿ, где Tᵢ = 𝟙[пасс pᵢ применён]
Потенциальные исходы (potential outcomes framework): Y(t) : {0,1}ⁿ → ℝ — производительность программы при воздействии t

Целевые величины

Величина Определение
Average Treatment Effect τᵢ = 𝔼X[Y(Tᵢ=1, T₋ᵢ) − Y(Tᵢ=0, T₋ᵢ)]
Conditional ATE τᵢ(x) = 𝔼[Y(Tᵢ=1, T₋ᵢ) − Y(Tᵢ=0, T₋ᵢ) | X = x]
Interaction Effect γᵢⱼ = 𝔼[Y(Tᵢ=1, Tⱼ=1) − Y(Tᵢ=1, Tⱼ=0) − Y(Tᵢ=0, Tⱼ=1) + Y(Tᵢ=0, Tⱼ=0)]

Задача

Дано: выборка 𝒟 = {(xₖ, Tₖ, Yₖ)}ₖ₌₁ᴷ, где Tₖ ~ Uniform({0,1}ⁿ) — рандомизированные эксперименты.

Найти:

  1. Оценки τ̂ᵢ для всех pᵢ ∈ P
  2. Оценки γ̂ᵢⱼ для всех пар (pᵢ, pⱼ), i ≠ j
  3. Граф зависимостей G = (P, E), где E = {(pᵢ, pⱼ) : |γᵢⱼ| > θ}
Обозначение: T₋ᵢ = (T₁, ..., Tᵢ₋₁, Tᵢ₊₁, ..., Tₙ) — вектор воздействий без компоненты i.

Почему каузальный вывод?

Проблема корреляционного подхода

ML-модель говорит:
«loop-unroll коррелирует с высоким speedup»

Но это может быть потому, что loop-unroll чаще применяют к программам с циклами, которые и так легче оптимизировать.

Каузальная модель говорит:
«loop-unroll вызывает +5% speedup для программ с циклами»

Контролируем характеристики программы (конфаундеры) и измеряем истинный эффект.

Преимущества каузального подхода

Аспект ML (корреляции) Causal Inference
Вопрос Что обычно происходит вместе? Что произойдёт, если применить пасс?
Интерпретация Чёрный ящик Понятные причинно-следственные связи
Обобщаемость Ломается при смене распределения Каузальные связи устойчивы
Взаимодействия Сложно выявить Явно моделируются через γᵢⱼ

Какие вопросы позволяет решить?

✓ Отбор пассов:
Какие пассы имеют нулевой эффект и могут быть исключены?
✓ Порядок применения:
Если A создаёт возможности для B, то A должен идти раньше.
✓ Конфликты:
Какие пассы не стоит применять вместе (γ < 0)?
✓ Синергии:
Какие пассы усиливают друг друга (γ > 0)?

Методология исследования

Сбор данных

  • ~20–30 ключевых проходов LLVM
  • Рандомизированные комбинации
  • ~5000–10000 экспериментов на бенчмарк
  • Контроль: фиксированный seed, среднее по 5 запускам

Метрики производительности

  • Время выполнения (основная)
  • Размер кода (code size)
  • Время компиляции
  • Инструкций на цикл (IPC)
  • Cache misses (через perf)

Методы каузального анализа

  • Causal Forests (econml) — оценка гетерогенных эффектов CATE
  • DoWhy — фреймворк для каузального вывода с refutation tests
  • Propensity Score Matching — контроль confounders

Ожидаемые результаты

Планируемые выходные артефакты

1. Оценки каузальных эффектов
Количественная оценка влияния каждого прохода на производительность
2. Матрица взаимодействий
Синергия (γ > 0) или антагонизм (γ < 0) между парами проходов
3. Граф зависимостей
• Enabling-рёбра: A → B
• Disabling-рёбра: A ⊣ B
4. Рекомендации
Порядок применения проходов на основе каузальных зависимостей

Пример гипотезы для проверки

mem2reg → instcombine имеет положительный эффект взаимодействия (enabling), так как продвижение памяти в регистры создаёт паттерны для комбинирования инструкций.

Заключение

Основные тезисы

  • Проблема оптимизации компилятора актуальна — стандартные уровни не оптимальны для конкретных программ
  • Существующие ML-подходы находят корреляции, но не объясняют причинно-следственные связи
  • Каузальный анализ позволяет понять структуру зависимостей между проходами
  • Результаты могут быть использованы для построения более эффективных эвристик
